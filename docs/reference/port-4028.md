# Goldshell BOX port 4028 (cgminer socket)

cgminer's classic socket API, `intminer 5.4.2`, on TCP 4028. It needs no token
and bypasses the web backend. Model context: the
[matrix](README.md#model-and-firmware-matrix).
Evidence: [notebook, Port 4028](../firmware-api.md#port-4028-no-token).

## Which units answer

- SC-BOX and SC5 Pro II answered with no token.
  `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-15]`;
  `[verified: SC5 Pro II, MCB_V3_3, fw 2.2.0, 2026-09-15]`
- SC Lite answered, four boards, with `voltage` and `powerid` but no `current`.
  `[reported: SC Lite owner, MCB_V4_3, fw 2.2.0, 2026-09-22]`
- HS-BOX: `[unverified]`.

## How to talk to it

Send one JSON object, read until the miner closes the connection. The reply
ends in one NUL byte. `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-15]`

```
{"command":"devs"}
```

A browser cannot open a raw TCP socket, so a web page still has to read
`/dbg/minerinfo`.

## Commands

| Command | Answer | Tag |
|---|---|---|
| `{"command":"devs"}` | `DEVS`: one object per hashboard, same keys as the `[PGAn]` blocks of `/dbg/minerinfo`; valid JSON | `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-15]` |
| `{"command":"summary"}` | unit totals: `Elapsed`, `MHS av`, `MHS 20s`, `Accepted`, `Rejected`, `Hardware Errors`, `Device Hardware%`, pool percentages; no temperatures or fans | unit not recorded in the notebook, `[unverified]` per model |
| `{"command":"stats"}` | malformed JSON (objects run together, `}{`); `temp_max` reads 0 | unit not recorded in the notebook, `[unverified]` per model |
| `{"command":"pools"}` | the pool URL and user | unit not recorded; carries the pool user, so do not store it |

`devs` keys: `Device Elapsed`, `MHS av`, `MHS 20s`, `Nonced`, `Accepted`,
`Rejected`, `Hardware Errors`, `Device Hardware%`, `clock`, `fan0..fanN`,
`tstemp-0/1/2`, `overheat`, `rebootcnt`, `hwerr-ration`. The SC5 Pro II adds
`voltage`, `current` and `powerid`.
`[verified: SC5 Pro II, MCB_V3_3, fw 2.2.0, 2026-09-15]`

## Why it is useful

- It has neither the token race nor the request-burst crash of the web backend,
  and it needs no login. Its values matched the HTTP read within a poll.
  `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-15]`
- What gbox does: it reads port 4028 first (since 0.8.0) and falls back to
  HTTP. Its discovery sweep never touches port 4028.

## Voltage on the SC-BOX is not a measurement

- The SC-BOX's `devs` carries a `voltage` of 0.41, in an undocumented unit that
  is not the SC5 Pro II's millivolts. It carries no `current` and no
  `powerid`, so no firmware watts figure exists on that unit by either
  transport. `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-15]`
- It is the setpoint echoed: on 2026-09-21 all 1778 logged rows read exactly
  0.41, through 162 W, 184 W and 221 W stretches at the same clock and through
  samples under 50 W. `[verified: SC-BOX, MCB_V5_4, fw 2.2.5, 2026-09-21]`.
  Not checked during a board-absent episode, which would close it.
- On the SC5 Pro II it is millivolts at the supply (11750).
  `[verified: SC5 Pro II, MCB_V3_3, fw 2.2.0, 2026-09-15]`
- On the SC Lite it read 9330 on all four boards across five reads a minute
  apart, while the plan said 9100, so it is not the setpoint there. Whether it
  moves with load is unobserved.
  `[reported: SC Lite owner, MCB_V4_3, fw 2.2.0, 2026-09-22]`
